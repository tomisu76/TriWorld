# TriWorld project instructions for Hermes

These are persistent rules for every Hermes session in this repository.
They are not a phase prompt and must never restart the project from Phase 0.

## Mandatory session bootstrap

Read these files in this order:

1. `docs/CURRENT_HANDOFF.md` — authoritative continuation checkpoint
2. `docs/hints/HERMES_VERIFICATION_RULES.md` — evidence and claim protocol
3. `HERMES_START_HERE.md` — documentation routing

Then inspect `git status --short --branch` and the exact HEAD. Continue from the
checkpoint. Do not repeat completed audits, regenerate evidence, or restart an
earlier phase unless the user explicitly requests it or current evidence proves
the checkpoint wrong.

`HERMES_TRIWORLD_MASTER_PROMPT_2026.md` is an architectural reference. It is
not a command to bootstrap an empty repository and is not mandatory reading for
every session. Read only the sections relevant to the current task.

If `docs/CURRENT_HANDOFF.md`, Git state, installed artifacts, or runtime logs
disagree, stop before editing and report the discrepancy. Git and preserved
runtime evidence outrank prose summaries.

## Non-negotiable project rules

- The goal is a deterministic, portable, loadable, and genuinely drivable
  BeamNG level, not merely a ZIP.
- Model road topology, physical geometry, visual layers, collision, and AI
  navigation separately.
- A `DecalRoad` is not physical collision. A SUMO network is not a 3D road.
- Never guess BeamNG Lua/editor or serialized scene formats. Verify against the
  exact installed version, an engine-saved golden, and a runtime canary.
- Italy is a benchmark and optional local dependency, not a redistributable
  asset pack.
- Preserve unrelated user changes. Do not reset, clean, overwrite installed
  mods, edit skills, commit, or push unless the current task authorizes it.
- Every significant claim must use one of the evidence states defined in
  `docs/hints/HERMES_VERIFICATION_RULES.md`.
- Static validation never proves BeamNG runtime loading, rendering, collision,
  AI navigation, or save/reload persistence.

## Working style

Make the smallest falsifiable change. Preserve the failing artifact and log
before any fix. Generate artifacts through the generator, never by accumulating
manual `fixed2`, `fixed3`, or similar ZIP patches. One test run must use one
immutable ZIP identified by SHA-256.

At the end of a task, update `docs/CURRENT_HANDOFF.md` and
`docs/implementation-status.md` with exact HEAD, working-tree state, evidence,
remaining uncertainty, and the next safe action.
